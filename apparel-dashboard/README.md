# 服饰经营数据看板

线上地址：https://kingsleylam1213-creator.github.io/report-dashboard/apparel-dashboard/

报表导航：https://kingsleylam1213-creator.github.io/report-dashboard/home.html

本看板通过公开的 GitHub 仓库与 GitHub Pages 托管。页面数据也可公开访问，这是本次迁移已确认的访问方式。其他报表入口维持原样。

## 每次更新线上数据

1. 把最新 Excel 放回“产品管理、商品管理、库龄管理、新版履约单管理、销售代码”五个文件夹。
2. 双击同一层目录中的“更新线上看板.cmd”。从 GitHub 下载的副本对应入口为仓库根目录“更新服饰看板.cmd”。
3. 保持命令窗口打开。脚本会重读各文件夹最后修改的非临时 `.xlsx`，不使用缓存，再提交到 GitHub 并等待 Pages 发布。
4. 只有看到“线上更新成功”才表示本次数据已上线。脚本随后会打开线上网址，直接刷新即可使用。

更新全过程不需要 GPT、Codex 或手工复制请求。需要联网；本机安装 Python（带 openpyxl）和 GitHub CLI，并已用具有仓库写权限的账号运行 `gh auth login`。现有电脑会优先复用已安装的 Python 运行时；在其他电脑使用 `python -m pip install openpyxl` 准备依赖即可。

原来的“更新看板.cmd”仍只更新本地网页。“打开服饰看板.cmd”打开本地快照。原 Sites 地址不再作为这个入口的更新目标。

## 检查和失败处理

脚本将网页、更新工具与首页链接一起提交为一个 GitHub 版本，并保留仓库其他文件。遇到并发更新时会读取最新版本重试，不强制覆盖其他提交。每次发布后检查 Pages 状态、线上快照标识及四个网页文件的 SHA-256，避免把提交成功误报成上线成功。

发生错误时窗口会保留原因。记录位于本地 `outputs/github-publish/last-result.json`，包括提交号、来源快照、最终状态或错误。提交后的 Pages 构建若失败，原已发布网页继续保留；可排除网络或源文件问题后再次双击更新。

不会上传原始 Excel、本地缓存、买家联系方式或登录密钥。GitHub 登录由 `gh` 管理，脚本不保存密码或 token。上传文件按固定清单选择，不会把工作区所有文件批量上传。

线上数据采用 gzip 压缩，在浏览器内自动解压以减少加载体积。请使用新版 Edge、Chrome、Firefox 或 Safari。压缩是体积优化，数据仍可公开访问，不是密码保护。

## 功能与口径

### 库龄历史变化

在“库存与库龄”中切换“历史变化与升级预警”，可查看各库龄段趋势、181天及以上及365天以上趋势、任意两期快照对比、SPU高库龄增长/下降排行，以及SKU/SPU变化明细。明细支持筛选、分页和导出两期各区间数量与变化量。

每次重建数据自动把库龄快照存入本地 `history/inventory-age/`；相同库存内容和库龄生成日期不重复归档。同日发生内容修订时保留独立版本，默认基准选择更早库龄日期的一期，不把同日修订当作自然滚龄。文件夹中保留的旧库龄Excel会自动回填历史；删除原Excel不会删除已保存的快照。

线上更新会先恢复GitHub已经归档的历史，再合并本地快照并一起发布。历史同时保存在GitHub的同目录中，换电脑或本地历史丢失时可恢复。历史索引若被其他更新修改，脚本会停止本次提交并要求重试，避免覆盖他人的历史。

预警按“仓库＋货主＋SKU”核对。库龄日期确实前进时，阈值以上数量从0变为正数，标记“首次出现更高库龄”；高库龄增加且低库龄减少时，标记“疑似滚龄”。只有高库龄增加但没有低库龄减少证据的，单列“高库龄数量增加”。新增记录、本期未出现、缺失或异常数量不会作为滚龄，也不会把未提供的数量自动当成0。

目前报表没有批次流转数据，不能确认同一批货的实际滚入数量。预警是针对区间变化的核对线索；明细保留两期原数和预警依据。只有一期时显示真实基准和单点，不补造过去的曲线或变化量。

保留经营总览、订单销量、库存库龄、刊登在售、SKU校验及数据口径页面。支持小、中、大字体，各页筛选、排序、分页、CSV导出，20张汇总卡片可展开对应明细并导出全部分页。

- 产品档案是单品、SPU、SKC、颜色、尺码、组合成分的主档；保留原始 SKU，不按固定连接符段数截取。
- 非空产品 SKU 优先精确匹配；空白时匹配平台 SKU 的完整边界。只允许已确认的唯一内部连接符补配、同 SPU 唯一前缀缩写组合及完整 `/`、`+`、`*数量` 组合表达式。未知关系留待核对。
- 在售组合覆盖单品，单独标记“仅组合在售”。待刊登按所选平台、店铺、站点判断。
- 默认已发货销量直接汇总“对应单品sku数量”，不重复乘商品数量。平台订单按平台、店铺和订单号去重，订单号为空时用履约单号。
- 库存是五个库龄区间数量之和，不等于可售库存；高库龄为181天及以上。共享仓库存不按店铺分摊，快照未出现某 SKU 不等于真实零库存。
- CSV 保留完整标识符；Excel导入时，将 SKU、商品ID和订单号列指定为文本，防止长数字精度损失。

## 技术入口

`tools/publish_github.py` 负责预检查、重读 Excel、固定文件清单提交、等待发布与线上文件核验。`tools/publish-github.ps1` 是 Windows 启动器。可加 `-CheckOnly` 仅检查权限与配置，或 `-BuildOnly` 仅构建本地，均不上传数据。数据解析规则保留在 `tools/build_dashboard_data.py` 与 `tools/prepare_data.py`。
